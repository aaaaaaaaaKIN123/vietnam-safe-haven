# Agent Data Guide

This file is the operating contract for any agent working with the research data
folder. Read this file before touching anything under `data/`.

## Purpose

The `data/` folder supports an empirical finance project on safe-haven assets for
Vietnamese equities. The project compares VNIndex, domestic SJC gold, global
gold, Vietnam government bonds, oil shocks, monetary policy variables and
optional crypto assets using GARCH-family, DCC/ADCC-GARCH, safe-haven
regressions, hedging effectiveness and Markov-switching robustness.

The main goal of this folder is reproducibility:

1. preserve original raw files;
2. standardize data through scripts;
3. create clean model-ready panels;
4. document every source and transformation.

## Non-Negotiable Rules

1. Do not overwrite or edit raw files directly.
2. Do not delete any existing data file unless the user explicitly asks.
3. Do not manually edit model-input CSVs. Regenerate them through scripts.
4. Do not mix raw, cleaned, feature and model-output files in the same folder.
5. Do not treat yield, yield volatility and bond total return as the same variable.
6. Do not use a simulated series as an official index without clearly labeling it.
7. If adding a new file, update metadata.
8. If creating a derived variable, document its formula and source columns.

## Approved Architecture

The approved architecture is intentionally compact. It keeps enough separation
for reproducible research without creating too many intermediate folders.

```text
data/
+-- 00_raw/
+-- 01_processed/
+-- 02_model_input/
+-- 03_model_output/
+-- metadata/
`-- scripts/
```

There is also an optional archive folder:

```text
data/_archive_legacy/
```

This archive contains earlier root-level imports and old API download outputs.
It is preserved for traceability only. New work should not read from it unless
the user explicitly asks to recover an old file.

If the folder has not yet been reorganized into this structure, preserve the
existing files and propose a migration rather than moving files silently.

## Folder Roles

| Folder | Role | Agent behavior |
|---|---|---|
| `00_raw/` | Original downloaded/imported files | Read-only. Never modify. |
| `01_processed/` | Cleaned panels and derived features: standardized dates, units, returns, spreads, stress dummies and bond returns | Generated by scripts. |
| `02_model_input/` | Final model-ready daily/weekly panels | Read for modeling. Regenerate, do not hand-edit. |
| `03_model_output/` | Data-pipeline-specific diagnostics or intermediate outputs, if needed | Do not use as the main research-results folder; write research outputs to `results/`. |
| `metadata/` | Data dictionary, source map, inventory and logs | Update whenever data changes. |
| `scripts/` | Reproducible data collection, cleaning and feature-building scripts | Modify carefully and document changes. |

## Critical Bond Warning

For this project, bond variables have different meanings:

1. `VN10Y yield` is a yield level, not a bond return.
2. `yield volatility` is a risk/stress indicator, not a bond return.
3. `bond TRI` is the correct series for bond asset returns.

Use `bond TRI` for hedging effectiveness and safe-haven asset comparison.
Use `VN10Y yield` or `Delta VN10Y yield` for interest-rate or bond-market
stress interpretation.

## Simulated TRI Disclosure

The file `chi_so_bond_total_return_vn.xlsx` is a simulated total return index.
It should be described as:

> Simulated Vietnam 10-year government bond total return index constructed from
> VN10Y yield using full bond pricing and reinvested interest return
> assumptions.

Do not call it an official HNX, VBMA, Bloomberg or Refinitiv index unless a
separate official source file is provided.

## Transformation Rules

Use these formulas unless the user explicitly approves a change:

- Price return: `r_t = 100 * log(P_t / P_{t-1})`.
- Yield/rate change: `d_y_t = y_t - y_{t-1}`.
- Bond yield changes in the term-structure module are stored in basis points:
  `d_y_t_bps = 100 * (yield_t - yield_{t-1})`, where yields are percentage
  points.
- Bond slope: `bond_slope_10y_1y = y_10y - y_1y` and
  `bond_slope_10y_5y = y_10y - y_5y`.
- Bond curvature: `bond_curvature_1_5_10 = y_10y - 2 * y_5y + y_1y`.
- Simulated 1Y/5Y TRI: reprice a semiannual-coupon constant-maturity par bond from `yield_{t-1}` to `yield_t`, then add daily carry `yield_{t-1}/252`.
- Global gold in VND per troy ounce: `XAU_USD * USDVND`.
- Global gold in VND per tael/luong: `(XAU_USD * USDVND) / 0.829426`.
- Gold premium: `log(SJC_sell_VND_per_tael) - log(global_gold_VND_per_tael)`.
- Bond asset return: `100 * log(Bond_TRI_t / Bond_TRI_{t-1})`.
- Policy rate daily alignment: forward-fill event-driven policy rate after
  sorting by date.
- Weekly data: use week-ending Friday where possible; use last available value
  for price/index/rate levels, then compute returns/changes from weekly levels.

## Quality Checks Required

Before using any panel for modeling, run or report:

1. duplicate dates;
2. missing values by column;
3. date range by column;
4. extreme returns/outliers;
5. unit consistency;
6. overlap period across core variables;
7. whether event-driven policy rate was forward-filled;
8. whether SJC unit is million VND/tael or VND/tael;
9. whether XAU/USD has been converted to VND before premium computation;
10. whether bond TRI, not yield change, is used as bond asset return.

## Agent Workflow

Use this sequence:

1. Read `data/AGENT_DATA_GUIDE.md`.
2. Inspect `metadata/` files.
3. Audit raw file availability (run `python data/scripts/00_audit_raw.py` for core, and `python data/scripts/01a_collect_sectors.py` for sectors).
4. Run or update scripts in `scripts/`.
5. Generate cleaned panels and features into `01_processed/` or `01_processed/sectors/`.
6. Generate final model inputs into `02_model_input/` (run `02_build_model_input.py` for core, and `02a_build_sector_input.py` for sectors).
7. For the bond term-structure extension, run `python data/scripts/02b_build_bond_term_structure.py`.
8. Run quality checks (run `03_quality_checks.py` for core, and `03a_sector_quality_checks.py` for sectors).
9. Write research outputs to `results/`; use `03_model_output/` only for
   data-pipeline-specific outputs if explicitly needed.
10. Update metadata (ensure `sector_model_input_report.md`, core reports or
    `bond_term_structure_report.md` are updated).
11. Report what changed and what remains uncertain.

## What Not To Do

Do not:

- rename raw files without recording the mapping;
- replace user-imported files with downloaded versions silently;
- merge daily and weekly data in one model-input file;
- forward-fill market prices before computing returns unless explicitly needed
  and documented;
- treat missing market holidays as zero returns without explicit justification;
- use BTC/ETH in the core sample without acknowledging shorter sample periods;
- use policy-rate event rows as if they were regular daily observations without
  forward-filling;
- merge sector indices into the core daily return sample, as it will reduce the core sample length by 5 years. Always use the separate `sector_extension` directory.

## Preferred Language

For user-facing reports and metadata explanations, use Vietnamese with formal
academic wording. Technical variable names can remain in English snake_case.
