# Agent Project Guide

This file is the project-level operating guide for any agent working in this
workspace. Read this file before making changes.

## Project Context

This is an Advanced Econometrics empirical finance project. The research tests
whether safe-haven assets protect Vietnamese equities during stress periods.

Core assets and variables:

- VNIndex as the Vietnamese equity market proxy.
- Domestic SJC gold as the main local safe-haven candidate.
- XAU/USD converted into VND as the global gold benchmark.
- SJC gold premium as the Vietnam-specific contribution.
- Simulated Vietnam 10-year government bond total return index as the bond asset return.
- Vietnam 1Y, 5Y and 10Y government bond yields as the bond term-structure channel (all tenors are fully available).
- Interbank rate and SBV policy rate as monetary-tightening variables.
- Brent and WTI as oil-price shock proxies.
- BTC and ETH as optional crypto extension assets.
- VIX as a global risk control.

## Main Research Question

Do domestic SJC gold, global gold converted into VND, Vietnam government bonds
and selected digital assets act as hedges or safe havens for VNIndex during
equity-market stress, oil-price shocks and monetary-tightening periods?

## Non-Negotiable Rules

1. Do not delete user-imported files.
2. Do not overwrite raw data.
3. Do not manually edit model-input CSV files; regenerate them from scripts.
4. Do not move files out of `data/00_raw/` unless the user explicitly asks.
5. Do not treat bond yield, yield volatility and bond total return as the same variable.
6. Do not call the simulated bond TRI an official index.
7. Store model outputs only under `results/` or `data/03_model_output/`, depending on whether the output is data-pipeline-specific or paper-analysis-specific.
8. Keep final manuscript assets in `paper/`, not scattered across root.
9. Update metadata when adding data or changing transformations.
10. Report assumptions and limitations clearly.

## Modeling Pipeline

Recommended sequence:

1. Data audit: raw coverage, date ranges, missing values.
2. Data processing: standardized daily and weekly panels.
3. Feature construction: returns, gold premium, bond TRI returns, stress dummies.
4. Preliminary diagnostics: descriptive statistics, ADF/PP, Jarque-Bera, ARCH-LM.
5. GARCH-family models: GARCH(1,1), GJR-GARCH or EGARCH.
6. Correlation models: CCC-GARCH, DCC-GARCH, ADCC-GARCH.
7. Safe-haven regressions: lower-tail thresholds and stress interactions.
8. Hedging effectiveness: hedge ratios, portfolio weights, variance reduction.
9. Markov-switching robustness: normal vs stress regimes.
10. Crypto extension: BTC and ETH, with shorter sample caveat.
11. Bond term-structure extension: 1Y/5Y/10Y yield changes, slope and curvature.
12. Sector extension: 10 HOSE GICS sector indices daily/weekly returns (from 2015).

Model parameters should be changed in `src/models/model_control.yaml`, not by
hard-coding values inside model scripts. Methodological justification should be
kept aligned with `src/models/model_method_map.yaml`.

## Current Research Design Notes

- Core sample should start around `2010-01-04`, based on overlap between XAU/USD,
  oil, VN10Y, bond TRI and other core series.
- Policy rate is event-driven and should be forward-filled before daily modeling.
- SJC gold is in million VND per tael/luong and must be converted before premium computation.
- XAU/USD must be converted to VND before comparing with SJC.
- Bond TRI is the correct asset-return series for the bond safe-haven test.
- VN10Y/VN5Y yield changes are stress/channel variables, not asset returns.
- The bond term-structure extension is generated by
  `data/scripts/02b_build_bond_term_structure.py`. Current outputs are fully
  integrated with 1Y, 5Y, and 10Y yields.
- BTC/ETH should be treated as extension samples because their histories are shorter.
